# Changelog

## [Unreleased] - Renamed to GoreLab (2026-10-17)

### Changed
- **The system is named GoreLab now** (it was "Gore Simulator"; that name is taken in the Unity Asset Store). Namespace `GoreLab`, assemblies `GoreLab.Runtime`, `GoreLab.Editor`, `GoreLab.Editor.Studio`, `GoreLab.Setup` and `GoreLab.Pooling.Runtime`, define `HAS_GORE_LAB`, folder `Assets/Scripts/GoreLab`, repository `GoreLab`. The Gore Studio window and the `Tools > Gore Studio` menu keep their names. Nothing else changed; older entries below keep the old name they were written with.

## [Unreleased] - Editor studio look (2026-10-17)

### Editor
- **Gore Studio moved to `Tools > Gore Studio` and got its logo on the tab (not run in Unity).** The menu item no longer sits in a `GoreLab` sub-menu, and the studio shell puts the brand logo before the window name on the tab, like the other studio windows. The hints and docs that named the old path now say `Tools > Gore Studio` (the older entries below keep the path they were written with).
- **Studio editor look on the shared Veneer (not run in Unity).** New assembly `GoreLab.Editor.Studio` (`Editor/Studio/`, gated by `HAS_UNITASK` and `HAS_VENEER`, references the runtime, `GoreLab.Editor` and `Veneer.Editor`) with `GoreBrand` (accent #C2185B, logo and banner from `Editor/Brand`, style sheet `Editor/Brand/GoreBrand.uss`), `GoreCharacterStudioEditor` and `GoreProfileStudioEditor` (the two Inspectors as `VeneerInspector`s), and `GoreStudioShell` (the Gore Studio window shell). `GoreLab.Editor` stays ungated (it keeps the baker, the window and the IMGUI helpers) and exposes its internals to the new assembly (`Editor/AssemblyInfo.cs`). The old `GoreCharacterEditor` and `GoreProfileEditor` stay as the fallback Inspectors inside `#if !HAS_VENEER`, so exactly one editor per type is active; the profile summary they both show moved to the UI-free `GoreProfileSummary`. `DependencyGuard` keeps `HAS_VENEER` set while `Veneer.Editor` exists (an optional system: nothing is offered or installed).
- **Gore Studio window shell (not run in Unity).** `GoreStudioWindow` gets `CreateGUI` (`GoreStudioWindow.Shell.cs`): when the studio assembly registers its shell the window shows a title bar with a state pill, tabs, a two-pane layout, and the Target, Fill material and Apply cards as kit cards; the Skinned meshes, Body parts, Cloth parts, Worn equipment and static panels and the 3D preview stay IMGUI inside `IMGUIContainer`s (the same methods, so selection, Undo, hotkeys and the orbit view are unchanged). Without the kit, or if building the shell throws, the window draws itself with `OnGUI` exactly as before. `GoreGUI.Accent` and the preview's active-button colour now use the brand magenta-red.

## [Unreleased] - phase G1

First version, not yet run in Unity.

### Added
- **E4: static meshes break into pieces (not run in Unity).** The Gore Studio's static mode and a new run-time component `GoreBreakable` (editor side built with a tools-programmer agent). Pure core in `Runtime/Core` (checked by 65 scratch programs outside the project): `GoreMeshTopology` (flat triangle numbers, adjacency, closed test), `GoreTessellator` (extra triangles by longest-edge bisection, crack free, seams kept, optional triangle selection), `GorePartitioner` (seeded random division along the surface, every piece connected, every separate piece of the mesh gets a seed), `GoreBreakBuilder` (the piece meshes, with a lid cone into the solid on every broken edge of a closed mesh, flat normals, box-mapped texture coordinates, weight = whole volume times surface share), `GoreBreakPlanner` (the studio's preview and the setup go through the same call). Data: `GoreBreakProfile` (pieces, fill material, density, despawn, spin, and the studio's choices so it reopens as left) and `GoreBreakPiece`. Run time: `GoreBreakable` (`Break(point, force, radius)`, `Sever(piece, impulse)`, `IsPieceBroken`, `BrokenCount`, `IsAllBroken`, `ResetBreakable()`, events `Severed` / `Restored`; no Update; pieces made at the first break; `GoreDetached` also carries a broken piece and has `Breakable` / `Piece`). Editor: `GoreBreakBaker` (saves the piece meshes as assets, fills the profile again in place, puts the component on the object), and the studio's static panels. `GoreRuntimeMeshes` is public now (`Read`, `Build`, new `BuildStatic`). The design decision "a lid is a fan from the middle of the broken edge" was changed for static meshes during the checks: a surface patch with a fan on the surface is flat and has no volume, so the lid is a cone into the solid.
- **Entering the Edit mode lets go of the picked object (not run in Unity).** In Object mode the picked object stayed picked (and the rest dimmed) after Tab, and a click on nothing in Edit mode only cleared vertices. Now entering the Edit mode clears the picking at once; the tools still work on the mesh that was picked (`GoreStudioModel.EditRow`; a picked piece of clothing means nothing to edit) and the label at the top says *Editing: <mesh>* (or *all body meshes*); leaving the mode puts the tools back on every mesh.
- **Click on nothing lets go of the body part; A twice selects none (not run in Unity).** In Object mode a click on empty space now also lets go of the chosen body part (as if its colour was clicked again), not only of the picked object. In Edit mode *A* selects everything and *A* again, when everything is selected already, selects nothing (*Alt + A* still selects nothing at once).
- **The chosen body part's lid and ring stand out (not run in Unity).** When a body part is chosen (its colour clicked), its lid is strong red and every other lid is faint, and its ring is a thick white line (7 px); the other rings are 3 px again (the first redo had made them 2 px and they were hard to see). With no part chosen all lids are the same as before. The lid mesh keeps the cut of each vertex (`GoreStudioRow.LidCut`) and is painted again by `GoreStudioModel.Recolor`.
- **The lids show again when a look hides the naked meshes (not run in Unity).** With *Dress* and a look, the naked meshes the clothes replace were hidden by switching their *Show* off, and the lids and cut lines belong to those meshes, so they vanished even with Lids on. A look now only marks the mesh (`GoreStudioRow.HiddenByLook`): its skin is not drawn, its lids and cut lines are; in Edit mode the hidden meshes are shown again, because the body is what is being edited. *Show* in the Skinned meshes card is left as the user set it.
- **The studio shows a dressed character as it looks in the game (not run in Unity).** The preview only tied the clothes to the skeleton, so the skins of the look (chest, gloves, pants), the skin materials of the clothes and the naked parts a piece hides were missing: bare patches of skin showed through. New optional interface `GoreLab.IGoreLookPreview` (`Runtime/Data`): a data asset dropped into the Worn equipment card may implement `PreparePreview(character, items, hidden)`; the studio calls it after *Dress* with its working copy of the naked character, the roots of the clothes and a collection to add the body renderers the look hides (those meshes are hidden in the preview). The studio remembers the materials of the naked meshes first and gives them back (and shows the hidden meshes) at *Undress*. The GoreLab still knows nothing about any dressing system: the project's `NHanceLookData` implements it (`NHanceCustomization/NHanceLookData.GorePreview.cs`, `#if HAS_GORE_LAB`, the class is `partial` now): it sets the look's skin items on the avatar and calls `NHAvatar.Clean()` (the naked parts get their skin layers), then for every worn item hides the naked parts the item replaces, gives the item the skin materials when it copies the skin, and adds the materials its mappers list to the body parts (what `NHAvatar.Compile` does, from the avatar's public data; the N-Hance code is not changed). A look that is not an `IGoreLookPreview` is simply dressed as before.
- **Gore Studio preview: Object and Edit modes, picking, X-ray, overlay toggles, clearer colours (not run in Unity).** The owner found the preview hard to read (colours alike, cut marks and vertex dots everywhere). Colours: a humanoid's parts have fixed colours (the left side blue and green, the right side orange and pink, the head purple, dark at the upper part of a limb and light at the hand or foot; any other cut a saturated golden-ratio hue; the body a darker grey). Modes like Blender: **Object** (default; click picks a whole body mesh or piece of clothing by a ray against the posed triangles, a click on nothing lets go, the rest is dimmed, a hover label names the object under the mouse and says what a cloth piece does; no vertex dots or wire) and **Edit** (Tab toggles; vertex, edge, face, click and paint selection and the *Add to cut* bar work only here, on the picked body mesh, or on all shown body meshes when none is picked; a picked cloth piece says it is set up in the Cloth parts card). Pressing a mesh name in the Skinned meshes card picks it. **X-ray** draws the coloured meshes translucent (alpha about 0.45) so layers show through each other. **Lines** and **Lids** toggles hide the cut rings and the lid fans (both on by default; rings 2 px, lids a little fainter). No data or run-time change.
- **The Gore Studio panel was redone for clarity (not run in Unity, layout not seen).** The owner found the panel hard to understand, so the editor work was given to a tools-programmer agent and reviewed here. Rows are now fixed columns with column headers (*Cut Lids Show* over the meshes, *Part Bone* over the body parts, *Show Piece R/W* over the cloth), short notes at the top of each card, an empty state for Cloth parts, a clearly separate *Fill material* section in Body parts (the chosen part with its colour, its material, a *To all* button, and "n of 13 set"), a box under the selected cloth piece with the Cut tick box, Body side / Part side or Goes with, and each piece of a divided mesh on two lines. Scan and Dress share one row; labels are at most two words and the long explanations moved to tooltips. Humanoid cuts and a Rig change keep the fill materials by cut name. `GoreGUI` has new row helpers (`Row`, `TakeLeft`, `TakeRight`, `Swatch`, `CheckBox`, `ColumnHeader`, `Caption`, `Tip`, `Heading`, `BeginInset`). No data or run-time change.
- **A fill material for every cut (not run in Unity).** The lid on the part and the stump on the body used one default red material. Each cut now has its own (`GoreCut.FillMaterial`, `GoreBaker.CutSpec.Fill`): in the Body parts card of the Gore Studio, the *Fill material* section names the body part whose colour was clicked and sets its material, and *To all* copies that material to every part. Empty = the default red material as before. Apply puts it on that cut's lid and stump renderers (every mesh's), so flesh for a limb, wood for a table (the static meshes of a later phase) are a choice per cut. Pressing Humanoid cuts makes the cut list again and forgets the materials. Set up again to use it.
- **Every flying piece flies on its own (not run in Unity).** The pieces set to Fly in a divided mesh came off as one body (a set flies off as one body per segment, and pieces with the same owner share a segment). Now each piece that flies is a set of its own (`GoreCharacter.PieceGroups`), so each becomes its own flying body; the pieces that stay with their part still share one set. No new Apply needed.
- **Several sets of one worn mesh all appear at the first cut (not run in Unity).** A mesh set up as Pieces (or Cut with a flying side) is made as several sets that share one original renderer (the pieces that follow, the pieces that fly). At the first cut `EnterCutMode` switched the original off after the first set, so the later sets saw it switched off and never showed their parts: the flying pieces disappeared from the body at the first cut of any limb, left and right alike, and never flew. What each set shows is now decided for all sets before any original is switched off. No new Apply needed.
- **Skin layers (extra materials) survive the cut (not run in Unity).** After the first cut the body lost its chest, glove and trouser skins of the N-Hance look (the parts and the part that came off were bare skin). Cause: a look system layers those skins as EXTRA materials on the naked renderers (`sharedMaterials` longer than the submesh count; Unity draws the last submesh again with each extra material), and the parts were given only one material per submesh. `GoreCharacter.PartMaterials` now appends the source's extra materials to a part that holds the source's last submesh (the parts keep the submeshes in the source's order), at the first cut (the baked parts) and for worn pieces that are split at run time. A piece that is not split already kept all its materials. The detached part carries them too. No new Apply needed (run-time code only).
- **Every divided piece can be cut or not (not run in Unity).** With *Divide* on (the two bracers, the two trouser legs) the pieces were only given a part and Follow / Fly; the owner wanted to decide for each piece whether it is cut. Each row now has a *Cut* tick box after its name: not ticked = the part it goes with (Auto or chosen) and Follow / Fly as before; ticked = the piece is cut along the body parts, with *Body: Follow / Fly* and *Part: Follow / Fly*. At run time the pieces that do the same when cut share one set (`GoreCharacter.PieceGroups`: follows, flies, follows with a flying body side, flies with a flying body side; the other pieces are left out of each set), `GoreClothRule.PieceCut` and `PieceBodyFlies` keep the choices. Set up again to write the rules.
- **Cloth parts card made simple: Cut or not, Auto, Divide (not run in Unity).** The owner found the modes (None / Cut / Whole / Pieces) tangled, so the card now asks only what it must. **Cut** (a tick box, needs Read/Write): the piece is cut along the body parts, with only *Body side* and *Part side*, each Follow or Fly (Follow on the body side = it stays). **Not cut** (the default): the piece goes whole with the part it hangs on, one row *Goes with: [Auto: Head | Body | any part]* and *Follow / Fly* (greyed when the part is the body: a piece that stays does not fly); this is what None and Whole were. **Divide** is offered only when the mesh holds separate pieces that Auto sends to different parts (a left and a right leg; hair is one piece going to the head, so nothing is offered): it lists the pieces, each with its own part and Follow / Fly. *Auto* is worked out from what the piece hangs on (the bone with the strongest weight of every vertex; a piece that hangs on the body only goes to the limb it lies along when it lies close to it, within half the limb's length, else it stays on the body, so a cape stays); the studio writes the result into the profile and remembers that it was Auto (`GoreClothRule.OwnerAuto`, `PieceAuto`, not used at run time). The run time is unchanged (modes Split, Whole, Pieces). Set up again to write the rules.
- **Cloth parts: *Cut type* with None on top (not run in Unity).** The mode list is now None / Cut / Whole / Pieces and is called *Cut type*. None (nothing happens to the piece, for a cape, say) is stored as Whole going with the body, so the profile and the run time did not change; Whole's *Goes with* now lists only the body parts.
- **Pieces: Auto is the nearest part, Follow / Fly for every piece (not run in Unity).** In the Pieces list, *Auto* now means what the "near ..." hint said: the part the piece is nearest to, measured to the limb (the line from the cut's bone to the next cut's bone, or to the farthest bone below it at the end of a limb), not to the bone alone, so a thigh piece is not taken for a knee piece. The studio resolves it when it saves (the profile holds the cut number) and shows it next to the row ("= LeftUpperLeg"); the preview paints it the same. Every piece also has its own *Follow / Fly* (the global *Then* is gone). At run time the pieces that follow are made as one set and the pieces that fly as another, each leaving out the other's triangles (`GoreMeshPipeline.Process`: a piece number of -3 leaves that piece out of the result), the second set with `GoreMeshSet.Fly`; `GoreClothRule.PieceFlies` keeps the choices. A piece that goes with the body never flies. Set up again to write the rules.
- **Pieces: By side (not run in Unity).** The owner's test of Pieces: the trouser mesh showed only "Piece 1": its two legs are joined at the top, so the mesh is one connected piece. When the mesh is one single piece, Pieces now divides it by itself (no switch: choosing Pieces is the choice) by the middle of the mesh along its x axis (between the smallest and the biggest x of the used vertices), giving a left and a right half that each get their own owner (`GoreMeshPipeline.Pieces`). Each piece row shows its vertex count and, as a hint, the cut whose bone is nearest to its middle ("near LeftUpperLeg"); the button still shows only that piece. The triangles the middle crosses are clipped by the splitter like any cut line. Limit: the side is by x in the mesh's own space, as exported (a character exported lying down would divide the wrong way: then use Cut or Whole). Set up again to write the rules.
- **Pieces: one mesh, each separate piece with its own part (not run in Unity).** A garment mesh made of loose pieces (the two trouser legs of one mesh) could only be given one owner in Whole. The Cloth parts card has a third mode, **Pieces** (needs Read/Write): the mesh is divided into its separate pieces (triangles that share a point, points at one place count as one: `GoreMeshPipeline.Islands`, the same numbers in the editor and at run time) and every piece gets its own *Auto* (its bone weights) / *Body* / body part; a button per piece shows only that piece in the preview, and *Then* Follow / Fly applies to all of them. At run time the choices become hand decisions of the splitter (`GoreMeshPipeline.Process(..., pieceSegment)`: the piece's vertices are included in its segment and excluded from the cuts below it, so it is never cut), kept in the profile as `GoreClothRule.PieceOwners` (cut number, -1 body, -2 by weights). A mesh that is one single piece says so and points to Cut. Set up again to write the rules.
- **Cloth rules are Cut or Whole; the foot cut took the shin with it (not run in Unity).** Reason found: the automatic rule for a worn piece that is not a clean ring (boots, greaves) sent the WHOLE piece to the part when the part held enough of it, and for that it moved every bone of the part it is cut from to the part too, so severing the foot took the boot up to the calf, severing the lower leg took the greave up to the thigh. The Cloth parts card now has two modes only. **Cut** (the default; needs Read/Write) cuts the piece exactly along the body parts by its bone weights, with no whole-piece rule: *Body side* Stay / Fly (the piece that is left on the body side stays or flies off too) and *Part side* Follow / Fly. **Whole** (no Read/Write): *Goes with* Body (the piece stays) or a body part, and *Then* Follow / Fly. Automatic and Stay are gone from the card (staying is Whole with the body). The studio saves a rule for every piece it dressed (`GoreClothRule.BodyFlies`, `GoreMeshSet.BodyFly`, `GoreClothMode` is now Auto = no rule, Split, Whole); a piece with no rule (never seen in the studio) still follows the old automatic rules. At run time `GoreCharacter.FlyBodySides` makes the body-side piece of a garment cut across by the cut fly off before the part is taken. Set up again to write the rules.
- **Dress, Cloth parts, two views (not run in Unity).** Gore Studio, Worn equipment card: *Scan again* is now *Scan*, and a *Dress* button puts the dropped clothes on the naked character in the preview (each piece's bones are tied to the character's bones of the same name, the way the dressing system does it at run time; the prefabs are found by the same scan, a component of a prefab such as a look's item stands for its prefab). The *Cuts* card is now *Body parts*; a new *Cloth parts* card lists the dressed pieces (a Show toggle, a colour for the part it mostly belongs to, whether its mesh has Read/Write) and, for the selected piece (the rest of the character is dimmed), what should happen when a body part is cut off: *Automatic* (as before), *Cut along the body (needs Read/Write)* with *Separated pieces: follow their part / fly off on their own*, *Whole, goes with a part (no Read/Write needed)* with *Goes with* (a cut, or auto by bones) and *Then: follows the part / flies off on its own*, or *Stays on the body*. The rules are kept in the profile (`GoreProfile.ClothRules`, found by the worn mesh; the owner is written by the cut's name in the studio) and written by Apply. Run time: `GoreCharacter` looks up the rule of every worn mesh (`GoreProfile.RuleFor`); a piece set to Whole or Stay is shown whole in the part chosen (no reading of the mesh), a piece set to Split is cut by its bones whatever it looks like (`GoreCutHint.Force` skips the ring, brush and keep-whole rules; an unreadable one falls back to whole with a warning), and a set with `GoreMeshSet.Fly` leaves the part it belongs to as a body of its own, thrown with a share of the part's force and some scatter (`GoreCharacter.Fly`). The preview has two views, next to the selection buttons (and the M key): the parts in flat colours (the pieces of clothing are painted by where they would go) and the character as it is, with its materials. Filling the cut ends of the clothing is NOT done yet. Set up again to write the rules.
- **A cut line with a gap makes one lid loop, not pieces (not run in Unity).** The lower arm cut (the elbow) had a crumpled sheet for a lid instead of a disc, on the part and on the body: the mesh has an open border there, the cut line is an open chain, and `GoreSplitter.Loops` started to walk it from an arbitrary edge in the middle, so one chain became two or three pieces, each closed by its own straight line (a fan over a fraction of the ring). Now an open chain is walked from its end (a point with one edge), and the open chains of a cut are joined end to end, nearest ends first, into one ring; what is left open is closed by a straight line when the lid is made, as before. The warning says one open chain for one gap. Set up again to bake the lids.
- **A worn piece that never touches the cut line is left to its bones (not run in Unity).** The armband of the upper arm stayed on the body: it is an island of the chest armour mesh, wholly on the upper arm's bone, and the rule for pieces that only brush a cut took the whole mesh to the body (most of it is chest). `GoreMeshPipeline` now leaves a cut alone for a mesh that has no seam point at that cut (nothing crosses the line): each island follows its own bones, so the band goes with the arm and the plate stays. The brush rule (whole to one side) applies only to a mesh that crosses the cut line without going round the limb (hair strands, a cape).
- **The head never splits what is worn; the studio says which left-out mesh belongs to a cut (not run in Unity).** Hair was still cut in half: it falls round the neck, so it makes one real ring at the neck cut and the ring test let it be split. `GoreCut.WornWhole` (set for the head by the setup, tooltip in the profile) makes the head cut split no worn piece at all: a piece goes whole with the head when at least 30 percent of it follows the head's bones (hair is mostly weighted to the head even when its long end hangs down the back), else it stays on the body (a cape). Limb cuts keep the ring test, so a glove or a sleeve is still split. The Gore Studio now writes under every mesh whose Cut is off but whose skin mostly follows a cut (the ears, the eyes and the brows follow the head): *Stays whole on the body, but most of its skin follows Head: tick Cut so it goes with it.* Set up again to write `WornWhole`.
- **The lids are the studio's again; worn pieces only go with a part (not run in Unity).** The owner's rule: what the studio preview shows for the naked character (the lid on the part and the stump on the body, each following the real cut line of the skin) is exactly what the game fills, nothing more and nothing less; what the character wears is never filled and never widens it. Done: the setup bakes the per-mesh lid and stump again; the flat disc, `GoreDiscBuilder`, `LidMaterial` and the equipment's `RebuildDiscs` are removed; the profile keeps `Sections` (per cut, the middle and the radius of the naked cut line, `GoreCutSectionMeasure`). A worn piece is cut by a cut only where it goes round the limb as one real ring (the biggest closed loop holds at least 10 points and 60 percent of the seam) at about the place and size of the naked cut (within 2 radii): a glove or a sleeve is split and the limb side comes with the part, without a lid; hair, a helmet, a cape and anything else that only brushes the cut is not split and goes whole to the side it mostly belongs to (hair with the head, a cape stays on the body). A worn mesh that cannot be read (no Read/Write) is not looked into at all: it goes whole with the part most of its bones belong to, shown by a duplicate renderer of the same mesh and carried on a frozen copy of its bones, so hair, helmets and capes need no Read/Write; only a piece that must be split along a limb does. The Worn equipment card says so and no longer warns before Apply. Set up again.
- **The lid discs keep to the cross-section (not run in Unity).** With armour on, the discs came out too wide and spiky (a head lid reaching over the shoulders, a big triangle at the shoulder, a sliver at the forearm): the outline was the hull of every point of every mesh's cut line, so hair, a cape and the wandering line of a blending joint stretched it, and the lid was across the bone above (a collar bone runs inwards while the arm hangs down). Now `GoreDiscBuilder` keeps only the points near the plane of the cross-section and not far from the limb's own radius (limits from the medians: within 0.8 typical radii along the axis, 2.5 typical radii out, then 1.8 times the median of what is left), and the baker stores the limb's own axis (`GoreDisc.TowardBody`, away from the next joint down the limb when the cut has one, else towards the bone above) which the lid is across. Set up again.
- **`[GoreWorn]` attribute (not run in Unity).** The Worn equipment card of the Gore Studio takes a prefab, a folder of prefabs, or any ScriptableObject, and follows ONLY the fields of a ScriptableObject that carry `GoreLab.GoreWornAttribute` (on an object reference or a list of them it marks exactly those; on a field with a serializable class or a list of classes it marks every object reference inside; a marked field may also hold a component of a prefab, which stands for the prefab). A data asset with nothing marked gets a note in the card. This replaces the first version, which followed every reference of a dropped asset. The attribute belongs to the GoreLab and does nothing at run time; a project that has its own data (a look, a loadout) puts it on its fields, inside `#if HAS_GORE_LAB` when the code must compile without the GoreLab. The Gore code knows nothing about any clothing package.
- **Worn equipment card in the Gore Studio (not run in Unity).** Drop what the character can wear (prefabs, a folder of prefabs, or any asset that refers to them, like a look: references, also to components of prefabs, are followed three steps): `GoreWornScan` lists the skinned meshes found, says which are not readable and `Make them readable` ticks Read/Write in their models and reimports them. Apply asks first when some are still not readable (make readable and apply / cancel / apply anyway), and the Apply area shows a warning. The dropped assets are kept in the profile (`GoreProfile.WornSources`, editor only, not in a build).
- **Equipment (worn pieces) is cut too (not run in Unity).** A character dressed at run time (the N-Hance look system disables the naked body meshes and instantiates armour, hair, boots... with their own skinned renderers) was cut only where the editor setup had prepared meshes, so the worn pieces stayed on the body and the naked pieces under them came off. Now `GoreCharacter` looks, when it starts, when it is enabled again and whenever `RefreshEquipment()` is called (two frames later, after the equipment has tied its bones to the skeleton), at every enabled skinned renderer it does not know and cuts it along the same cuts: the mesh is read into arrays (`GoreRuntimeMeshes.Read`), split on a worker thread (`GoreMeshPipeline.Process`, plain arrays, the same `GoreSplitter` the editor uses), and the part meshes are built on the main thread; the result is cached per mesh, profile and bone mapping (`GoreEquipmentCache`, cleared on scene unload), so the next character in the same armour costs nothing. The parts are switched-off renderers next to the piece, in the character's combined view of renderer sets. The lids are made again from the points of the character's own cut lines (now kept in `GoreProfile.Discs[].Points`, with `AnchorFromCut`, so set the character up again once) and the worn pieces together, so armour is closed by a lid as wide as the armour. A worn mesh must have Read/Write on (Unity cannot read a mesh at run time otherwise: `Mesh.AcquireReadOnlyMeshData` throws); without it one warning names the mesh and the piece stays on the body. `GoreCharacter` is `partial` now (`GoreCharacter.Equipment.cs`). A piece put on after the first cut is cut after `ResetCharacter`.
- **The part's skin is worked out from the bones, not baked.** `SkinnedMeshRenderer.BakeMesh` of a renderer that was only just switched on returned the bind pose, so the part skin did not sit where the lids and the blood were; `GoreCharacter.SkinNow` does the skinning sum itself (up to four bones per vertex, normals, tangents, UVs, colours and submeshes kept).
- **One flat lid per cut, made from every mesh together (not run in Unity).** A character made of pieces (boots, trousers, torso, head, hands) has a cut line in each piece, and the per-mesh lids closed some sides and left others open (a piece with no closed seam got none; a piece's own open rim stayed open). Now `GoreSplitter` also returns the points of every cut line (`GoreSplitResult.SeamPoints`, closed or not), `GoreDiscBuilder` (pure) takes the points of all the meshes that have Lids on, finds the outline round them (the convex hull as seen along the limb) and fills it with a fan facing the body (for the part) or the other way (for the stump), and `GoreBaker.BuildDiscs` saves two meshes per cut in `GoreProfile.Discs`: the lid on the part in the space of the cut's bone, the stump in the space of the bone above (both from the bind pose matrices, so the pose does not matter), with `GoreProfile.LidMaterial`. At run time `GoreCharacter` puts the lid on the part when it comes off (at the bone's pose, riding the part) and a stump disc on the bone above (the stumps of cuts below go with the part; `ResetCharacter` removes them). The setup no longer bakes the per-mesh lids and stumps (a profile made earlier keeps and uses them); the *Lids* switch of a mesh now means "its cut line shapes the lids". Set the character up again in the Gore Studio.

### Changed after the first review (same phase)
- The stump is skinned to the bones above the cut (the bones of the part that comes off are replaced with the nearest bone above it), so it stays on the body; the bone of a cut is squeezed to 0.001 scale at the cut and restored by `ResetCharacter`.
- A cut's seam counts the edges against every segment that does not come off with it (the other leg at the crotch), and open chains and self-touching seams are reported; the lid's normal and flat UV come from the loop's own plane.
- A set is shown after the first cut only when its source is enabled and active; materials changed at run time are carried over; `ResetCharacter` restores the original's earlier state.
- A rebake reuses the `GoreCharacter` component (it used to fail and leave the character without parts); every `GoreParts` container is removed by `Clear`; asset names are made safe; orphaned mesh assets are deleted; assets are created in one batch.
- `BakeMesh` already carries the renderer's scale: the snapshot is placed with a scale of 1 (it was scaled twice); render settings are copied to the parts and the snapshots; a part uses continuous collision detection and ignores only active colliders; a cut with no skin throws nothing.
- Setup refuses an unreadable mesh with the Read/Write instruction and warns about blend shapes, UV channels 4 and up, non-triangle submeshes and vertices with more than four bones; a mesh with Lids off is not searched for seams.
- The setup no longer demands Read/Write on the characters' models (Unity lets the editor read any mesh outside Play mode; the first version refused unreadable meshes by mistake). It is refused in Play mode, and when Unity itself refuses a mesh it says how to fix it and that Read/Write can be unticked again afterwards.
- The setup window lost its *Output* options and its *Last result* card (the result and its warnings go to the Console): a character that is already set up fills its own profile again, new profiles go to `Data/`, and the lids use the default red material. A mesh that has no skin on a segment (boots on an arm) is no longer warned about; a cut that no mesh has skin for is.

### Changed after the first Unity test (same phase)
- **The cut line is clipped through the triangles.** The splitter used to give every vertex to the segment its bone weights favoured and every triangle to the majority of its vertices, so the seam was a staircase of whole triangles: jagged lids with spikes, seams that did not close, lids missing on some cuts. Now each cut is the line where the share of weight on its bone and below is one half; the triangles it crosses are clipped (new vertices on the edges, all attributes blended, bone weights blended and cut to the four strongest), so the seam is one smooth closed ring and the lid is a clean fan. Area is conserved by the clipping (checked). `GoreSplitResult` gained `Vertices`, `Positions` and `Weights` (the refined vertices: the source ones first, then the new ones); every index of a part or lid points into them, and the baker blends the rest of the mesh data from them.
- **The skin that stays no longer follows the part.** Squeezing the bone of a cut pulled the blended skin round the joint (up to half its weight) towards the squeezed bone, so the ring of skin shrank out of line with the lid (spikes, a glaring neck). Now a cut gives the renderers that stay helper transforms under the bone above the cut, at the bind-pose offset of each bone of the part (`GoreMeshSet.BindPoses`), so the skin follows the bone above rigidly and matches the stump's lid; `ResetCharacter` gives the renderers their own bones back and removes the helpers. The squeeze stays only for what hangs on the bone. A profile made before this change has no bind poses: set the character up again.
- After a review by the technical-artist agent: the crossing vertex of an edge is computed from its two ends in an order that depends on their positions (the copies of an edge that a texture seam duplicated now weld into one ring); a vertex made on a cut line counts as exactly on it when triangles are assigned; a bind pose that cannot be a transform (zero, mirrored, not a number) makes the skin follow the bone above the cut without the offset and warns once; a profile without bind poses warns once; the lids' bone weights get a final pass; `Gore Cap.mat` itself is now matt (no specular highlights or environment reflections).
- A second Set up no longer rewrites the mesh assets of the first one in place (`CopySerialized`): Unity kept the drawing data of the old mesh and every part stopped rendering with "does not match the expected mesh data size and vertex stride". The meshes of an earlier setup are deleted and made again.

### Gore Studio, phase E2 trimmed and phase E3
- The Face mode and the Cuts mode were removed from the preview's toolbar (the owner did not need them): Vertex and Edge remain; a cut is highlighted by clicking its colour square in the list (which is also the cut a selection is assigned to). Alt + left drag no longer orbits there; the middle mouse does.
- **Decisions by hand (E3).** With a cut active, the selected vertices can be set to **Include** (they go with the part that comes off with that cut, whatever their bone weights say), **Exclude** (they stay on the body side) or **Auto** again; *Clear cut* takes every decision for the cut back. Decided vertices of the active cut are drawn green (include) and red (exclude) in the preview; the coloured parts update at once. The decisions are saved in the profile (`GoreMeshSet.Overrides`, `GoreVertexOverride`, `GoreOverrideKind`) and read again when the character is opened.
- In the splitter: `GoreSplitInput.Overrides`. Every vertex has a share per cut in one table (from the bone weights or from the decision); an include is 1 for the cut and every cut above it and 0 for any cut that is neither above nor below, an exclude is 0 for the cut and every cut below it (excludes first, so an include wins); a vertex made on a cut line gets its shares blended from its two ends (it used to recompute them from blended weights, which forgot a decision by hand next to it). The cut line is clipped through the edges next to a decided vertex like anywhere else, so it stays one clean ring (an included vertex with no included neighbour makes an island of its own with its own ring, by design).
- The X-ray switch was removed (the owner found no use for it): the selection tools only ever pick what faces the camera.

### Gore Studio, UI rework after the E3 test
- **Add to cut / Remove from cut now fill the region.** A selection (a ring, a strip, a patch) is the line to go up to: *Add to cut* puts the selected vertices and everything between them and the part the cut already has into the cut; *Remove from cut* gives back what lies between the part's edge and the selection. A fill only happens when the selection really closes the region (it must not touch a part of the body that has nothing to do with the cut, and must not cover nearly all of the segment the cut comes from, or empty the whole part); otherwise only the selected vertices are decided and the bar says why. `GoreSplitResult.SourceShares` (the bone-weight shares of the source vertices, before any decision) and `GoreStudioMeshEdit.Decide` (breadth-first fill over the welded vertices, the selection is the wall).
- The panel lost its Selection, View and Checks cards. The preview has: a toolbar at its top left like Blender's header (two square buttons: click select and paint select; a little apart, vertex, edge and face, drawn as icons; the mode in use is blue; keys 1, 2, 3 and C), paint select (C: hold and drag to paint, Shift + drag deselects, the wheel sets the brush size, C or Esc go back to clicking), a bar at the bottom (how many vertices are selected, the cut they are for, Add to cut / Remove from cut / Reset / Clear all) and hints at the bottom left. The face mode is back. The Target card now reads Prefab, then Mesh type, then (for a skinned character) Rig. A problem with the character is shown above the Apply button.
- After a review: the fill starts only from groups that are inside the cut and not selected (a selected ring is a wall, inside or not); whether a group is inside a cut counts the decisions of every cut by the splitter's own rules (an exclude from an upper cut also takes it out of the cuts below); a click in the preview takes the keyboard focus out of a text field; hotkeys ignore Ctrl and Command (except Ctrl + I); *Frame selection* (Numpad .) keeps the zoom limits and the box F frames (`GoreOrbitView.FocusOn`); the brush circle is clipped to the preview and follows the mouse only where needed; the projection of every vertex per mouse event is cached (`GoreOrbitView.BeginProjection / ProjectCached`) and a stroke only tests what is near it; overlay meshes keep 32-bit indices; the humanoid confirmation is asked at click time.
- **The selection is the cut line.** *Add to cut* / *Remove from cut* no longer flood from the part: the selected vertices cut the mesh into pieces; the piece that is the part's side (most of the cut's own vertices, fewest of the segment it is cut from) keeps the cut, and *Add to cut* gives it what lies between it and the selection, while whatever the other side had of the cut (the V of skin under the neck) goes back to the body; *Remove from cut* sends the selection and the other side back to the body. A selection that does not cut the mesh in pieces (half a ring, a patch) decides only the selected vertices and the bar says so. `GoreStudioMeshEdit.Decide(kindsByCut, cut, kind, segmentParent, out included, out excluded, out separated)`.
- The paint brush circle was drawn offset (the mouse position is already relative inside a clip). The bar is smaller (*Add to cut*, *Remove from cut*; *Reset* and *Clear all* are gone) and its title no longer runs into the cut list. **Ctrl + Z / Ctrl + Y** undo and redo the selection and the decisions (50 steps; selecting, painting, boxing and adding to a cut are steps). The hint line at the bottom left was replaced by a round **info button** at the bottom right (like the Easy UI's) that opens a list of every mouse and key action.
- **The cut is chosen by itself.** The bar's *Cut* list starts on **Auto**: the cut whose part (by the bone weights) is nearest to the middle of the selection is used and highlighted, so *Add to cut* is never greyed out only because no cut was picked (it used to say "Choose a cut" and disable both buttons). Picking a cut in the list or by its colour square in the Cuts card is a choice by hand and stays until Auto is picked again. `GoreStudioMeshEdit.NearestInside`.
- An edge loop (Alt + click) that stops short of itself is joined over a gap of up to ten edges, so a ring round a body part closes; the "no line" message tells how to fix a gap.
- **An arc is closed into a ring.** When the selection does not cut the mesh into pieces, `Decide` looks for one connected arc (its two ends are the ends of its longest path) and joins the ends by the shortest way over the mesh that stays off the arc (Dijkstra, at most 2.5 times as long as the arc); the groups on that way are selected too, and then the selection is a line like a whole ring (the toast says how many vertices closed it). Two separate bits or a patch cannot be closed. `GoreStudioMeshEdit.CloseArc`, `Decide(..., out closed)`.
